# 故障经验与排查提醒

案例来自WHHW_7A5C、其参考代码及化工业与发电扩展的用户反馈。区分已确认问题、尚待验证的修复结果与通用风险；不把项目数值和补丁套到所有Mod。用户澄清或新证据出现后更新记录，已排除的故障不继续修补。

## 已确认的日志或显示问题

**元素名称再次哈希。** 旧代码把重蒸汽哈希-231445647写成elementId名称，数字字符串再哈希得到日志中的-339679289，导致Element与Substance错位。统一规范字符串身份，核对最终查找与相变，不用全局Enum补丁掩盖。

**早期材质为空。** 加载Prefix直接new Material(source.material)报空引用。选择当时可用模板并核对最终绑定；材质补齐仍不能解决身份错位，两者分别排查。

**动画名重复后缀。** 目录和加载器都追加_kanim，注册成_kanim_kanim。按实际注册键对照代码与包结构。

**瓶装链遗漏。** 只注册Element/Substance没有物品实体，擦拭和装桶不完整。补原生实体与容器行为，液气固三态分别考虑。

**问号图标与巨大图标。** ui动画不等于ui符号；补符号后，建筑几何和位移直接搬进菜单又导致图标遮挡。分开各入口的资源和尺寸，核对PNG、UV、几何、边界和变换。

**占地与可见图形不一致。** 全画布比例正确，透明边距却让主体没有贴合格子。检查轮廓、原点、底座和全循环；不要把机器改成实心砖。

**发电厂标签遗漏。** 发电组件存在但房间分类不全。对照同类原版标签，连同芯片和小人调优考虑；反应器不能冒充发电设备。

**蓝图仍显示成品。** place/construction只复用成品图层。按原版各阶段制作线稿及施工外观，保持原点和占地一致，不破坏原生有效/无效着色。

**调优显示缺失，实际增益正常。** 用户最初看到固定10kW说明和悬浮卡片缺功率，怀疑调优失效；后来实测确认实际为1.5倍。最终问题是信息缺失或口径不清，不能继续记录成“增益未接通”。保留原生增益，补动态显示，不再乘一次。

**重冰没有可见碎块。** 用户报告刷出/挖掘后没有可见地面物。源码有实体配置，但动画缺参考固体碎块中的idle1/2/3，且复用不合适的世界位移。补了专用图与状态并做资源检查；本记录不声称新版已完成游戏实物验收。格子材质、实体生成、动画可见性和相变分别查。

## 从参考实现学到的提醒

### 化工业项目的掉落与显示反馈

- **碎块悬空。** 用户0.1.1截图显示废硫堆与砖面有间隔。源码核对确认原生物理原点停在地面上方一个碰撞半径，而自制动画把图底放在原点；三档均需补偿。0.1.2资源增加对应基线检查，旧资源实际失败、重生成后通过，尚未取得新版游戏贴地验收。计算关系见[元素与物品](elements-and-items.md)。
- **产物落到建筑外格。** “建筑旁”被实现成占地外一格，与用户要求的原版精炼器出料体验不符。用户澄清后改到占地内，翻转与备用格保持该契约。不要把一次选错的偏移值变成所有建筑的默认值。
- **卡片像单独加了一套提示。** 泛化的未运行行与原生自动化禁用行同时出现，功率和产热却缺失。改为自身组件复用原版格式和数据契约，保持手动产热算法；不能为了显示把原生自动热量重新打开。

上述修订已有源码核对、编译与离线检查；瓶罐和轨道注册链已核对，实际搬运、渲染及高温相变仍待游戏验证。原始用户反馈不能同时证明所有其他入口都已运行。

### 原生行为与参考接口

BottleFlipper是参考Mod的特殊逆水组件，不是原版瓶装必需行为。先查组件来源、职责和依赖。

参考程序集可能只保留类型与签名，没有方法体；可证明接口存在，不能证明内部算法或实际运行。参考资源能说明约定，仍应核对目标游戏消费者。

运行属性在菜单未初始化Prefab上可能为空。区分预览基础数据与实例动态数据，不用全局异常吞噬遮掩运行错误。

## 通用风险，不能写成已发生事实

- 共用生成器可能让多个对象有同类缺陷，按共同原因扩大检查；不要虚构“其他对象修复后仍报错”的历史。
- Tinkerable标记不一定证明增益，固定基础说明也不证明失效；检查实际属性。原生已加成后再乘倍数会重复增益。
- 规则可能只检查旧问题、遗漏新失败条件。需要自动检查时，用实际错误资源检验它能否发现问题，不强制所有小修复建测试框架。
- 程序画图和增加分辨率不等于原版精细程度；在结构、材质和同场协调上继续打磨。
- 编译或解析通过不代表导航、房间、相变和存档已验收；按实际证据表述。
